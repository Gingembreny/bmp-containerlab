## NetCalyx interoperability issue

A reproducible parsing failure occurs with FRRouting 10.6.1:

```text
RouteMonitoringMessageError
  -> BgpUpdateMessageParsingError
  -> Ipv4PrefixError
  -> NomError: Eof
```
After the parsing error, NetCalyx closes the TCP connection and FRRouting reconnects automatically.
Observed behavior:
- Static pre-policy monitoring can remain connected.
- Post-policy triggers the error during initial synchronization.
- Dynamic withdraw/re-advertisement also reproduces the error.
- pmacct handles the same events without terminating the BMP session.
A reproducing PCAP is available under tests/netcalyx/.
